# moonbitJobShop 验收增强设计

## 目标

将现有的确定性作业车间调度核心扩展为可用于制造排程原型的 MoonBit 库：支持可解释的派工策略、可重复的改进搜索、动态事件重排、多目标分析、结构化输出和可复现实验，同时保持无第三方依赖、跨 stable target 可验证。

## 设计边界

- 公开 API 继续集中在 `src` 根包，避免把用户需要构造和匹配的领域类型放在内部包中。
- 所有算法接收不可变意义上的 `ScheduleInput`，输出 `Result[Schedule, String]` 或明确的分析记录；不引入全局状态和随机系统调用。
- 搜索算法使用确定性种子和轻量的本地 RNG，因此同一输入可以复现相同结果；它们是可替换的启发式，不宣称求得数学最优解。
- 动态重排只负责生成新排程和事件诊断，不修改传入订单；设备故障通过不可行区间约束表达。
- benchmark 使用固定生成器和实际 CLI 执行结果；仓库只记录命令、输入规模、目标值和测量环境，不硬编码无法复核的性能承诺。

## 组件

1. `model` 扩展输入校验、订单优先级、设备日历、不可用区间和稳定的领域辅助方法。
2. `dispatch` 增加按 FIFO、最短加工时间、最早交期、最小松弛度和换型感知的确定性策略。
3. `search` 提供邻域交换、局部爬山、模拟退火式接受、禁忌搜索和小型遗传搜索；每个求解器都复用同一调度内核。
4. `dynamic` 提供订单插入、订单取消、设备故障和滚动窗口重排，并保留事件报告。
5. `metrics` 提供 makespan、延期、流动时间、换型次数、关键路径、瓶颈设备和加权目标。
6. `pareto` 提供目标向量、支配关系、Pareto 前沿和折中选择。
7. `format` 提供 CSV、ASCII 甘特图、摘要文本和稳定校验签名，便于 CLI 和上层 Web/终端使用。
8. `benchmark` 与 `cmd/benchmark` 提供固定规模数据集、结果摘要和实测运行入口。

## 错误与边界行为

空输入、重复 ID、负时长、未知设备、重复设备候选、非法设置时间、故障区间重叠、负搜索参数和空 Pareto 集合都返回明确的错误或空结果。所有区间计算统一采用半开区间 `[start, end)`，零长度区间不占用设备资源，负长度永远不被接受。

## 测试与质量

测试先覆盖公开行为，再实现最小代码；重点覆盖空数组、单工序、多候选设备、相同起始时间的稳定排序、换型、故障边界相切、动态事件和搜索预算为零等情形。CI 使用官方安装脚本，在 Ubuntu、macOS、Windows 上运行 `moon version --all`、`moon update`、`moon check --target all`、`moon test --target all`、coverage、格式和 API diff。

## 验收证据

验收时只报告实际命令输出：`moon check`、`moon test`、native 测试、CLI 输出、有效 `.mbt` 行数、GitHub 默认分支、许可证、提交历史和 Mooncakes 发布状态。申报书是只读输入，不参与 README 叙述，也不计入源码规模。
